## 2. 実施目的

受講者が、生成AIを用いて自らの担当業務の課題を解消できる状態になること。

一般的なAIの座学ではなく、受講者が現に担当している業務を題材とし、
受講者自身が実際に動く仕組みを構築する形式をとる。

職種別の受講目的は以下のとおり。

| 職種 | 現状の業務課題 | 受講により目指す改善 |
|---|---|---|
| 営業 | 案件情報をLINE・スプレッドシート・kintoneの3箇所へ重複して入力している。時間外のLINE問い合わせ対応が担当者の負担になっている | 生成AIとシステム連携による入力の一元化。定型的な問い合わせ応対の自動化 |
| プロモーション | 内覧会（歯科医院の開業イベント）の実績をkintoneへ手入力し、シフト管理を手作業で更新している | 実績集計とシフト反映の自動化 |
| カスタマーサポート | 会員サービスの登録作業（ID・パスワード発行等）が手動で、問い合わせ窓口が複数に分散している | 発行作業の自動化と受付窓口のオンライン化 |
| 営業・カスタマーサポート（共通業務） | 歯科医院の先生との印刷物制作のやり取り（打ち合わせ・データ整理・デザイン会社への転送）が手作業 | 依頼受付から入稿までのデジタル化 |

研修終了時点で、受講者が自社の業務改善を継続して進められる状態を到達点とする。

## 3. カリキュラム

| 回 | テーマ | 成果物 |
|---|---|---|
| 第1回 | キックオフ・生成AIの基本と繰り返し使える指示文 | 担当業務における時間短縮の記録 |
| 第2回 | 業務の棚卸しと、取り組む課題の決定 | 部署ごとの課題整理シート |
| 第3回 | 要件定義 | 要件定義書 |
| 第4回 | モックアップ（試作画面）で確かめる | モックアップ（試作画面） |
| 第5回 | データ構造と連携の設計 | 連携の設計 |
| 第6回 | 繰り返し入力をなくす | 実際に動く連携の仕組み（1件以上） |
| 第7〜8回 | 実績を自動で集計する | 実績集計の画面 |
| 第9回 | 顧客とのやり取りをデジタル化する | 試作版と、運用に載せるための課題整理 |
| 第10回 | 社内で使える状態にする・成果発表 | 社内手順書と、次の取り組み計画 |

上記は集中研修（全10回）の内容。集中研修のない週に、オンライン講座（全3回）を実施する。
各回の題材は、受講企業の実業務に合わせて設定する。
各回の実施日時・実施場所・実施内容と時間の内訳は、別紙「訓練カリキュラム（各回の実施内容）」のとおり。
